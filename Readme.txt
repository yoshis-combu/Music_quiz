==========================================================
 新規プロジェクト作成手順（このフォルダをテンプレートとして使う）
==========================================================

このフォルダは Claude Code + Jira 運用プロジェクトのテンプレートです。
新しいプロジェクト（リポジトリ）を立てるときは、以下の手順に従ってください。


----------------------------------------------------------
 1. 新規フォルダを作成する
----------------------------------------------------------

例: claude_<リポジトリ名>_env
（フォルダ名は任意。エージェントはフォルダ名を参照しない）


----------------------------------------------------------
 2. テンプレートからコピーするファイル・フォルダ
----------------------------------------------------------

以下を「そのまま」コピーする。

  CLAUDE.md                  … 運用ルール本体。テンプレートのまま。編集禁止
  PROJECT.md                 … コピー後に編集する（手順5参照）
  .gitignore                 … output/ __pycache__/ *.pyc PMnotes/ を除外
  .mcp.json                  … atlassian MCP 設定（project スコープ）
  .claude\                   … サブエージェント定義一式
      agents\coder.md
      agents\tester.md
  .vscode\                   … エディタ設定一式
      settings.json
      tasks.json


----------------------------------------------------------
 3. コピーしてはならないファイル・フォルダ
----------------------------------------------------------

  .git\                      … 旧リポジトリの履歴。新規プロジェクトでは
                               git init で新しく作る（手順6参照）
  src\ の中身                … サンプル実装（hello.py 等）は開発物であり
                               テンプレートの一部ではない
  output\ の中身             … 実行副産物はリポジトリ固有
  PMnotes\ の中身            … PM 資料（シナリオ書・メモ）はリポジトリ固有
  docs\ , tests\ の中身      … このリポジトリの開発物
  Readme.txt                 … この手順書。テンプレート元にだけ置く
                               （コピーしても害はないが不要）


----------------------------------------------------------
 4. 空で新規作成するフォルダ
----------------------------------------------------------

中身はコピーせず、フォルダだけを新規プロジェクト側で「空で」作成する。

  src\                       … 開発対象のコードを置く（必須）
  output\                    … 手動実行時の出力先（必須）
  PMnotes\                   … PM 資料の置き場。.gitignore 対象（必須）
  docs\ , tests\             … 必要になった時点で作成すればよい（任意）


----------------------------------------------------------
 5. PROJECT.md を編集する（編集するのはこのファイルだけ）
----------------------------------------------------------

  - リポジトリ名: <新しいリポジトリ名を記入>
  - 目的:         <このプロジェクトの目的を記入>

CLAUDE.md 本文の <リポジトリ名> は、すべてこの値を指す。
（例: リポジトリ名が SELL_SIG_AP なら、Jira の識別ラベルは
  repo-SELL_SIG_AP になる）

リポジトリ固有の技術ルールがあれば、CLAUDE.md の
「プロジェクト固有のルール」欄に追記してよい（無ければ空のまま）。


----------------------------------------------------------
 6. git リポジトリを初期化してコミットする
----------------------------------------------------------

  git init
  git add .
  git commit -m "chore: テンプレートからプロジェクトを初期化"

コミット前に git status で output\ や __pycache__ が
untracked に出ていないこと（.gitignore が効いていること）を確認する。


----------------------------------------------------------
 7. Jira 側の準備（PM が画面操作で行う）
----------------------------------------------------------

  - 定位置ビュー「決断待ち_<リポジトリ名>」を作成する
      project = DEV AND labels = repo-<リポジトリ名>
      AND status IN (Open, 要件定義中, Acceptanceチェック中)
      ORDER BY updated ASC
  - 横断ビュー「ラベル漏れ検出」が未作成なら作成する（全リポジトリ共通・1本のみ）
      project = DEV AND labels IS EMPTY AND statusCategory != Done
      ORDER BY created DESC

cloudId と project key（DEV）は全リポジトリ共通のため変更不要。
以降の運用ルールはすべて CLAUDE.md を参照すること。
